# 사용자 데이터 저장소

## Decisions

- 사용자가 입력하는 데이터(매매 기록 등)는 Supabase Cloud의 데이터베이스에 저장하고, 로그인은 Supabase Auth로 한다.
- 각 사용자는 자기 데이터만 읽고 쓸 수 있다(소유자 전용 권한).
- 연결과 인증 설정은 프로젝트의 `setup-supabase` 스킬 경로를 따른다.

## Boundaries

- 시장 데이터(가격·지표)는 이 결정의 대상이 아니다. [market-data-source](market-data-source.md)를 따른다.
- 브라우저 저장소(localStorage 등)를 사용자 데이터의 원본으로 쓰지 않는다. 화면 편의를 위한 임시 값은 예외다.

## Why

사용자는 휴대폰과 PC 등 여러 기기에서 같은 기록을 본다. 그래서 기기 밖에 있는 저장소와 로그인이 필요하다. 지금은 본인 혼자 쓰지만 나중에 다른 사람에게 공개할 계획이라, 처음부터 사용자별 소유 구조를 갖춰 두면 공개할 때 구조를 바꾸지 않아도 된다. Supabase는 데이터베이스와 인증이 한 서비스에 있고, 프로젝트에 설정 스킬이 준비되어 있다.

## Reconsider when

- Supabase 무료 플랜의 비활성 일시 정지나 용량 제한이 실제 사용을 반복해서 막을 때
- 다른 사람에게 공개하면서 요금이나 데이터 보관 조건이 맞지 않게 될 때

## Still-rejected alternatives

- 이 PC의 브라우저나 로컬 파일에 저장 — 휴대폰에서 같은 기록을 볼 수 없다. 한 기기에서만 쓰게 되면 다시 검토한다.
- Firebase — 프로젝트에 준비된 설정 경로가 없고, 문서형 저장소라 종목별 집계에 덜 맞다.
- 별도 DB(Neon 등)와 별도 인증 서비스 조합 — 두 서비스를 따로 연결해야 해서 개인용 첫 단계에 비해 무겁다.
