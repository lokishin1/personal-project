# 배포와 휴대폰 접속

## 사용자 결과

사용자가 휴대폰과 PC의 브라우저에서 같은 인터넷 주소로 앱을 연다. 로그인하면 어느 기기에서든 "종목 한눈에 보기"와 "매매 기록"을 같은 데이터로 쓴다. 증권사 앱으로 매매한 직후 휴대폰에서 바로 기록할 수 있다.

## 범위

- 앱을 Vercel에 배포하고, 기본 브랜치(`main`)에 병합된 내용이 배포되게 한다.
- 배포된 앱이 기존 Supabase 프로젝트(같은 계정과 기록)를 쓰게 한다.
- 새 가입을 막는다. 앱에서 가입 화면을 없애고, Supabase에서도 새 가입을 끈다.
- 로그인 뒤 이동 경로(`next`)로 외부 사이트에 보낼 수 있는 문제를 고친다. trade-journal 리뷰에서 나온 지적으로, `/\host`처럼 앞의 `//`가 아닌 값이 검사를 통과했다.

## 수용 기준

1. 배포된 주소에서 TSLA를 검색해 고르면 현재가, PER/PBR, 그래프가 보인다. Yahoo Finance가 배포 환경의 요청을 막지 않는다는 첫 확인이다. 실패하면 아래 "미뤄 둔 점"으로 넘어가고, 나머지 기준은 확인하되 이 작업을 완료로 보지 않는다.
2. 휴대폰 브라우저에서 배포된 주소로 로그인하면 PC에서 입력한 매매 기록이 똑같이 보인다.
3. 휴대폰에서 매매를 한 건 입력하면 PC에서 새로고침했을 때 그 기록과 다시 계산된 요약이 보인다.
4. 로그인 화면에 가입 탭이나 가입 버튼이 없다.
5. 앱 밖에서 Supabase로 직접 가입을 요청해도 새 계정이 만들어지지 않는다.
6. `next` 값이 `/\evil.example`, `//evil.example`, `https://evil.example`처럼 앱 밖을 가리키면, 로그인 뒤 앱 안의 매매 기록 화면으로 간다. `/stocks/TSLA`처럼 앱 안의 경로는 그대로 그 경로로 간다.
7. 로그인 상태는 휴대폰 브라우저를 닫았다 다시 열어도 유지된다.
8. 휴대폰 화면에서 "종목 한눈에 보기"와 "매매 기록"의 주요 정보와 버튼이 잘리지 않는다.

## 정해진 제약과 이유

- 호스팅은 Vercel이다. 근거와 재검토 조건은 [hosting](../../decisions/hosting.md)을 따른다.
- 데이터베이스와 로그인은 [user-data-storage](../../decisions/user-data-storage.md)를 따른다. 배포된 앱도 같은 Supabase 프로젝트를 쓰고, 공개해도 되는 연결 값(URL과 publishable 키)만 배포 환경에 넣는다.
- 시장 데이터는 [market-data-source](../../decisions/market-data-source.md)를 따른다. 이 작업에서 데이터 출처를 바꾸지 않는다.
- 새 가입을 막는다. `PRODUCT.md`에 적힌 대로 지금은 본인 혼자 쓰는 단계이고, 모르는 사람이 가입하면 무료 용량과 Yahoo 요청량을 함께 쓰게 된다. 다른 사람에게 공개하는 시점에 다시 연다.

## 가정 (바꿔도 되는 기본값)

- Vercel 기본 도메인(`*.vercel.app`)을 쓰고, 개인 도메인은 연결하지 않는다.
- Vercel 프로젝트와 GitHub 연결, 배포 환경 변수 입력, Supabase의 가입 끄기는 사용자가 직접 한다(계정 생성과 키 입력이 필요하다).
- Supabase Auth의 Site URL을 배포 주소로 맞춘다. 이메일 확인을 끈 이메일·비밀번호 방식이라 리다이렉트 주소는 추가로 필요 없다.
- 미리보기 배포(PR마다 생기는 주소)도 같은 Supabase 프로젝트를 쓴다.

## 범위 밖과 이유

- 개인 도메인, 홈 화면 앱(PWA) 설치: 휴대폰 브라우저로 쓰는 것이 확인된 뒤 필요하면 다룬다.
- Google 로그인: trade-journal에서 미룬 그대로다.
- Yahoo 요청 캐싱이나 속도 제한: 차단이 실제로 확인되기 전에는 하지 않는다.
- 비밀번호 재설정: setup-supabase 범위 밖이다. 비밀번호를 잊으면 Supabase 대시보드에서 직접 처리한다.

## 미뤄 둔 점

- **배포 환경에서 Yahoo Finance가 막힐 때의 대응:** 이 PC에서 실행하고 터널로 공개하기, 다른 지역(region)에서 실행하기, 데이터 출처 바꾸기 중 무엇을 할지는 수용 기준 1의 결과를 보고 정한다. 데이터 출처를 바꾸는 쪽이면 [market-data-source](../../decisions/market-data-source.md)를 다시 검토한다.
  - 그 전까지의 동작(임시): 막히면 기존 오류 상태("데이터를 가져오지 못했습니다", "현재가를 가져오지 못해 평가할 수 없습니다")가 보이고, 매매 기록의 입력과 수량·평균단가·실현 손익은 그대로 쓸 수 있다.

## 남은 위험

- Yahoo 차단은 시간이 지나 생길 수도 있다. 배포 직후 수용 기준 1을 통과해도 나중에 막힐 수 있다.
- 가입을 막으면, 두 계정 외에는 새 계정을 만들 수 없다. 공개할 때 설정을 다시 켜야 한다.
- 배포 주소는 누구나 열 수 있다. "종목 한눈에 보기"는 로그인 없이 쓸 수 있어서, 모르는 사람이 이 화면을 쓰면 Yahoo 요청량이 늘 수 있다.
